# Задание эксперта: калибровка юридического агента

Это **отдельное первое задание для юридического эксперта** (роль «эксперт»).
Оно предшествует основному заданию первого вклада
(`assignments/00-first-contribution/`): сначала вы калибруете агента на правовом
материале, затем собираете датасет.

**Это не юридическая консультация.** Задание учебное: оценивается качество
проверки и разбора, а не правовой совет.

## Цель

Научить агента извлекать правовые факты (норма → изменение → источник) так,
чтобы **эксперт явно указывал ошибки**, а агент их исправлял до состояния
`expert_approved=true`.

## Точные шаги

1. **Подготовьте сессию.**
   ```bash
   python3 legal-agent-calibration/scripts/legal_calibration_session.py init \
     --session-id ip-law-2026-<NNN> --journal sessions/<session-id>/session.jsonl
   ```
2. **Событие `task` — задание эксперта.** Укажите:
   - `source.authority` — нормотворец (напр. «Государственная Дума ФС РФ»);
   - `source.jurisdiction` — `RU` / `INT` / `EU` / … ;
   - `source.doc_type` — `statute`, `amending_act`, `case_law`,
     `international_treaty`, `official_guidance`, … ;
   - `source.title`, `source.identifier` — название и официальные реквизиты;
   - `source.effective_date` — дата вступления в силу (`YYYY[-MM[-DD]]`) или `null`;
   - `source.coordinate` — **точная** координата (статья/пункт/абзац/страница);
   - `payload.norm_id`, `subject`, `object`, `predicate` — ожидаемый факт.
3. **Событие `agent_answer`.** Агент извлекает факт: `norm_id`, `predicate`,
   `subject`, `object`, `effective_from`/`effective_to`, `confidence`.
4. **Событие `expert_review` — явные ошибки.** Эксперт перечисляет **конкретные**
   ошибки (не «не нравится», а что именно неверно):
   - неверный `predicate` (напр. `уточнена` вместо `изменена`);
   - неверная `norm_id` / `subject`;
   - неверная юрисдикция или тип документа;
   - неверная `effective_from` / `effective_to`;
   - неточная или неполная `source.coordinate`;
   - лишний/отсутствующий `object`.
5. **Цикл `correction` → `agent_answer` → `expert_review`.** Повторяйте, пока
   эксперт не примет ответ. Каждая правка — отдельное событие `correction`.
6. **Событие `final`.** Только эксперт завершает сессию:
   ```bash
   python3 .../legal_calibration_session.py append --journal ... \
     --role final ... # final всегда несёт expert_approved=true
   ```
   Агент **не может** утвердить себя: `role=final` без `expert_approved=true`
   отклоняется, а `expert_approved` запрещён в других ролях.
7. **Проверка и экспорт.**
   ```bash
   python3 .../legal_calibration_session.py validate --journal ...
   python3 .../legal_calibration_session.py export   --journal ... --out public/session.jsonl
   ```

## Правовая безопасность (обязательно)

- **Не юридическая консультация.** Не выдавайте результат за правовой совет.
- **Официальные источники предпочтительны**: pravo.gov.ru, vsrf.ru, WIPO Lex.
- **Никаких персональных данных и частных судебных дел** в сессии и экспорте.
- **Никаких полных сырых текстов** охраняемых произведений; норма излагается
  кратко и своими словами. (Официальные тексты законов и договоров — не объекты
  авторского права, но полные тексты в публичный экспорт всё равно не кладём.)
- **Проверяйте юрисдикцию, версию и даты действия** нормы. Устаревшая редакция —
  типовая ошибка калибровки.
- Публичный экспорт проходит редакцию: секреты, e-mail/телефоны и слишком
  длинные строки вычищаются (`session.py::redact_record`).

## Критерии завершения

Считать задание выполненным, если:

- [ ] в журнале есть хотя бы одна полная последовательность
      `task → agent_answer → expert_review → final`;
- [ ] есть **минимум одна** итерация правки
      (`correction → agent_answer → expert_review`);
- [ ] у каждого события заполнены все обязательные поля `source` и `payload`
      (валидатор: `errors=0`);
- [ ] финальное событие несёт `expert_approved=true`;
- [ ] `validate` возвращает код 0, `export` записан в отдельный публичный файл;
- [ ] эксперт подтверждает, что итоговый факт соответствует официальному
      источнику (юрисдикция/версия/даты сверены).

## Что дальше

Утверждённая калибровочная сессия — это пропуск к основному первому заданию:
**соберите 3 записи** об изменениях в статьи НПА по схеме курса и сдайте их в
`assignments/00-first-contribution/submissions/records-<ник>.jsonl`
(см. `assignments/00-first-contribution/README.md`). Калибровка **предшествует**
этой сдаче и её **не заменяет**.
